# vk cloud cdn, замеры

дата: 30 августа 2026. домен личный, источник по https, кэш через правила
на уровне ресурса.

| проба | результат | замечания |
|---|---|---|
| http-методы | get head post put delete options | patch отдаёт 405 |
| тело get | отбрасывается | напрямую до источника доходит 4096 байт |
| буферизация запроса | не буферизует | первый байт приходит сразу |
| стриминг ответа | стримит | 4 строки за 3.0 с |
| максимальное тело | не меньше 64 мб | предел не найден |
| обработка пути | сохраняется | хвостовой слэш и query не меняются |
| кэширование | не кэширует | после правил на уровне ресурса |
| таймаут простоя | около 228 с | долгий ответ обрывается |

## что не следует из документации

тело get отбрасывается. проверено на http/1.1 и http/2, через cdn приходит 0
байт, напрямую 4096. протокол, который кладёт данные в тело get, работать
не будет.

заголовки кэширования игнорируются. источник отдаёт no-store, cdn-cache-control
и surrogate-control, ответ всё равно кэшируется. управление только правилами
на уровне ресурса.

признак кэша нестандартный. вместо age отдаются cache: hit и x-cached-since.
проверка по одному age даёт ложноотрицательный результат.

очистка кэша по шаблону забирает не всё. записи, созданные до сброса по /*,
отдавались ещё больше получаса.

долгий ответ живёт около 228 секунд. от этого зависит период переподключения
для любого протокола с длинными соединениями.

## как воспроизвести

python3 probe/server.py --host 127.0.0.1 --port 9000
python3 probe/runner.py --through https://<cdn-домен>/probe --direct https://<origin-домен>/probe
